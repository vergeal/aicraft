# 桌面客户端设计规范

本目录是 opencode 桌面客户端的**唯一设计事实来源**。它规定界面"必须长什么样、为什么这样、违反时怎么判定"，不是竞品调研或灵感参考。

规范与代码冲突时，**以本规范为准**：代码是实现，规范是标准。发现不一致，开 issue 修实现，不允许反过来改规范迁就代码。

## 三、五条不可违背的红线

1. 组件内不写裸色值、裸字号、裸圆角；只引用令牌。
2. 状态样式由语义属性驱动（`aria-*`、`data-state`），不用 `.is-active`。
3. 玻璃只用于浮在内容之上的层，且必须有实色降级。
4. 单屏最多一个主要布局动画。
5. 用户可见文案全部走 i18n，简体中文必须齐全。

## 四、术语

| 术语 | 含义 |
| --- | --- |
| 表面 Surface | 一块有背景色的区域。层级从画布到浮层共五级 |
| 材质 Material | 表面的构成方式：实色、半透明、系统 vibrancy |
| 层级 Elevation | 视觉纵深，由阴影 + 描边 + 材质共同表达，不等于 z-index |
| 内容列 Measure | 正文的最大宽度，超过就失去可读性 |
| 胶囊 Capsule | `border-radius: 999px`，只用于单行、可数的场合 |
| 视线落点 | 进入页面时用户第一眼看的位置，每页只能有一个 |
| 连续表面 | 相邻区域共用一块表面，靠间距和分隔线组织，不靠卡片 |

## 五、适用范围

- 适用：`packages/desktop`、`packages/app` 的桌面客户端界面，以及其中的插件 GUI。
- 不适用：TUI、CLI 输出、第三方网页内容。
- 平台优先级：macOS 为第一验收平台，Windows / Linux 允许按 [18 桌面端](18-desktop.md) 的平台条款降级。
