# 19 · 治理

规范的权威性来自"谁能改、怎么改、改了怎么生效"。

## 1. 角色

| 角色 | 职责 |
| --- | --- |
| 设计系统负责人 | 批准新 token、新组件、新页面模式；裁决规范与实现的冲突 |
| 前端负责人 | 保证令牌落地、性能与平台一致性 |
| 提交者 | 提 PR 前自检 checklist，标注用到的规范章节 |

## 2. 命名

### 2.1 令牌

```
--v2-{组}-{项}[-{状态}]
```

- 组：`background` / `text` / `icon` / `border` / `overlay` / `state` / `elevation` / `material`。
- 项：只描述用途，不描述颜色或数值。
- 状态：`hover` / `pressed` / `focus` / `disabled` / `selected`。

禁止：`--red-500-button`、`--big-radius`、`--v2-new-thing-2`。

### 2.2 组件

- 组件属性命名与语义属性一致：`data-state`、`aria-checked`。
- 尺寸变体只有 `small / default / medium / large`。

### 2.3 文案 key

`模块.场景.含义`，见 [16 i18n](16-i18n.md)。

## 3. 新增令牌的四问

任何新 token 必须依次回答，答不上就不加：

1. **现有令牌不能覆盖吗？** 能用 `muted` 解决就不加 `secondary`。
2. **它表达的是用途还是数值？** 数值（如 `radius-14`）不允许成为 token。
3. **它在两种主题下都有值吗？** 缺一不可。
4. **它有明确的使用场景清单吗？** 写不出 3 个使用点，说明还不成熟。

四问通过后：先在本文档补一行，再在 `tokens.css` 落地，最后才允许组件引用。

## 4. 变更流程

```
提出（问题 + 现状 + 期望）
  → 影响面（哪些页面 / 组件 / 平台）
  → 方案（改规范 / 加组件 / 只改实现）
  → 评审（设计系统负责人 + 前端负责人）
  → 落地（文档 + tokens.css + 组件 + 视觉回归）
  → 记录（版本表 + 变更说明）
```

规则：

- 规范先改，代码后改。禁止"先上线再补文档"。
- 破坏性变更（删 token、改尺寸、改组件形态）必须列出迁移方式。
- 一次 PR 只做一类变更，便于回滚。

## 5. 冲突裁决

| 情况 | 裁决 |
| --- | --- |
| 代码与规范不一致 | 以规范为准，修代码 |
| 两处规范冲突 | 以更具体的一篇为准（组件 > 基础 > 原则） |
| 规范缺失 | 先补规范，再实现；紧急情况可先实现，但 PR 内必须补文档 |
| 平台限制无法遵守 | 走例外申请，记录在对应章节的"平台差异" |

**禁止**"以代码为准"。实现的先后不代表设计解释权。

## 6. 例外

例外必须满足：

1. 有明确技术或平台原因。
2. 范围最小（单个组件 / 单个平台）。
3. 有到期日或移除条件。
4. 写入文档的"平台差异"或"例外记录"。

例外记录格式：

| 位置 | 例外内容 | 原因 | 移除条件 |
| --- | --- | --- | --- |
| 例：Windows 顶栏 | 不使用玻璃 | Acrylic 在桌面背景下发灰 | 系统材质改善后复评 |

## 7. 废弃

```
标记 deprecated（文档 + 代码注释 + 替代项）
  → 保留一个 minor 版本
  → 下一个 minor 删除
```

废弃期间新代码禁止使用旧项；旧项只做兼容修复。

## 8. 版本

| 版本 | 含义 |
| --- | --- |
| major | 破坏性：删 token、改组件形态、改布局常量 |
| minor | 新增令牌、组件、页面模板 |
| patch | 澄清、示例、修正错别字 |

每次发版更新 README 的版本表与变更条目。

## 9. 文档维护

- 每个数值只能在一处定义：令牌值在 [02](02-tokens.md) 与 `tokens.css`，用法在对应章节。
- 章节间引用使用相对链接，不复制表格。
- 代码片段必须可运行（最小示例），不留伪代码。
- 新增页面模板必须同时给出 1440 / 1280 / 1024 三档行为。

## 10. 提交前自检

1. 用到的每个数值都能在文档里找到出处。
2. 组件五态齐全，状态由语义属性驱动。
3. 空 / 载 / 错三态已设计。
4. 深浅主题都验证过。
5. 键盘可完成主流程。
6. 新增文案有中文。
7. 过 [checklist](checklist.md)。
