## 两套实现速览

| | 实现 A | 实现 B |
|---|---|---|
| 样式技术 | 工具类框架编译产物 + CSS 变量 | 原生 CSS Modules |
| 主题实现 | **单层变量 + `light-dark()`** | **三层变量 + 属性开关** |
| Token 总数 | 2808 个（含组件局部） | 594 个唯一名（1061 定义） |
| 语义层 | `{角色}-{变体}-{状态}` 三维矩阵 | `static → alias → specific` 三级 |
| 间距 | `--spacing: 4px`，全量 `calc(*N)` | 无全局阶梯，组件局部变量 |
| 控件高度 | 10 档 `--control-size-*`（20→48px） | 按组件写死（按钮 36/28） |
| 圆角 | 2→32px + `--corner-radius-scale`（1 / 1.25） | 6 档 4→28px + `superellipse(1.5)` |
| 字号 | 固定阶梯 + 语义变量 | 固定阶梯 + **用户字号三档联动** |
| 字重 | 400 / **510** / **590** / 700 | 400 / 500 / 600 / 700 |
| 层级 z-index | 未集中（工具类） | 未集中（硬编码 1→1100） |
| 焦点环 | ring token | 2px，**仅键盘触发** |
| 共同点 | 0.5px 发丝描边抬升、8/12/16 主节奏、4px 基准 | 同 |

## 一句话结论

两套实现在**视觉语言**上高度收敛（0.5px 发丝边、4px 基准、8/12/16 节奏、无重阴影、玻璃材质），
真正的分歧在**工程表达**：实现 A 把语义压进一条 `light-dark()` 声明，靠命名矩阵横向展开；
实现 B 把语义分层，靠变量分表纵向收敛。见 [01-principles](01-principles.md) 第 3 节。

## 素材与可信度

- 实现 A 为加固后的构建产物：数值与命名可信，但组件边界与原始文件名不可恢复，因此只按「界面区域」归组。
- 实现 B 为原始源码：保留注释与设计意图，本文对「为什么这样写」的判断主要依据其代码注释。
- 归一化后可直接使用的产物是 [tokens.css](tokens.css)；它与两份原始素材不一一对应，冲突处取更保守的取值。
- 原始素材位于 `../styles/`，本文档不依赖其内部目录结构。
