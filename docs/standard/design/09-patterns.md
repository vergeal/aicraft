# 09 · 界面模式

## 1. 聊天输入区（Composer）

这是两套产品的核心组件，也是最容易做丑的地方。两边的参数高度一致：

| 参数 | 实现 B | 实现 A |
|---|---|---|
| 与内容同宽 | 内容宽 + 32px（`--composer-card-max-width`） | 内容宽 + 两侧 overhang |
| 圆角 | 由 `radius-token` 决定，单行为大圆角（≈24–28） | `--composer-radius: radius-4xl`（24–32） |
| 附件区内缩 | 8px（`calc(spacing*2)`） | `--composer-attachment-inset: 8px` |
| 堆叠间距 | 6px（`--composer-stack-gap`） | — |
| 顶部工具条内距 | 横 12 / 上 14 | 横 12 / 上 14 |
| 文本框最大高 | 336px | 按可用高度计算 |
| 阴影 | `elevation-composer` | `0 0 0 1px #0000000a, 0 2px 8px #0000000a, 0 4px 80px 8px #00000006` |
| 深色内高光 | — | `inset 0 0 1px 0 #fff3` |

**结构**（从上到下）：

```
┌──────────────────────────────────────────┐
│ 附件/引用区（有内容才出现）                 │
├──────────────────────────────────────────┤
│ 输入区（多行自增高，封顶 336px 后内部滚动） │
├──────────────────────────────────────────┤
│ 底部操作条：左 模型/工具   右 发送/停止    │
└──────────────────────────────────────────┘
```

**要点**

1. **单行与多行圆角不同**：单行是胶囊级大圆角，多行要收小一档，否则四行文本装在一个"胶囊"里很怪。实现 A 用 `radius-token-composer-single-line` 单独处理。
2. 输入框外扩 16px（总宽 +32）是为了让焦点环和浮起的图标不贴边。
3. 发送按钮在"无内容 / 有内容 / 生成中"三态间切换，**宽度不变**（图标位互换），避免布局跳动。
4. 附件缩略图圆角 = 容器圆角 − 内缩 − 4px 补偿，公式化而不是写死。
5. 深色主题下的输入框需要 `inset` 高光，否则在深底上"陷进去"看不见边界。

## 2. 会话消息流

| 参数 | 值 | 来源 |
|---|---|---|
| 消息块间距 | 16px | 实现 B `--assistant-block-gap` |
| 同一轮内行距 | 4px | 实现 B `--chat-flow-gap` |
| 会话项间距 | 16px | 实现 A `--conversation-item-gap` |
| 分组项间距 | 4px | 实现 A `--conversation-grouped-item-gap` |
| 正文列宽 | 680–1000px（clamp） | 实现 B |
| 长文阅读宽 | 730px | 实现 A |

**规律**：**"块间 16、块内 4"**。同一轮对话内部的段落/工具调用紧凑排列，不同轮之间留出明显间隔。这比统一 12px 更能表达结构。

消息流还必须处理：

- 代码块水平滚动不撑宽（`min-width: 0`）
- 超长 URL 断行（`overflow-wrap: anywhere`）
- 工具调用卡片可折叠，折叠后保留一行摘要
- 滚动到底部的"回到底部"按钮（离底 > 一屏时出现）

## 3. 设置页

| 元素 | 规格 |
|---|---|
| 设置卡片背景 | `settings-card-fill` = `bg-layer-2` |
| 卡片描边 | `settings-card-stroke` = `border-l4` |
| 卡片圆角 | 12–16 |
| 行高 | 44（标签 + 控件）或 56（含说明） |
| 行内布局 | 左标签（14/22）+ 右控件，`justify-content: space-between` |
| 分组标题 | 13/20，`label-tertiary`，距上一组 24px |
| 页面最大宽 | 720–760px（居中） |

**要点**

1. 设置项**不做卡片堆叠**，同一组用一个卡片 + 内部 1px 分隔线，否则页面会碎。
2. 每项右侧控件的宽度要固定（如 120px / 180px），不要随内容变。
3. 危险操作单独成组，放在最底部，按钮用 danger 变体，且需要二次确认。
4. 修改即时生效的项不设"保存"；需要保存的表单才出现底部粘性操作栏。

## 4. 空 / 载 / 错 / 禁用

| 状态 | 做法 | 规格 |
|---|---|---|
| **空** | 插图（`illustration-*` 三色体系）+ 一句说明 + 主操作 | 插图最大 160–200px，文字 14/22 `label-secondary` |
| **加载（首屏）** | 骨架屏，不用 spinner | `bg-skeleton`：浅 `rgba(0,0,0,.04)` / 深 `rgba(255,255,255,.08)`，1.5–2s 呼吸 |
| **加载（局部）** | 16px spinner，原地替换图标位 | 不动布局 |
| **加载（>3s）** | 加一行"正在…"文案 | 13/20 `label-tertiary` |
| **错误** | 图标（`state-error-primary`）+ 原因 + 重试 | 不用全屏红块 |
| **禁用** | `opacity: .4–.5` + `cursor: not-allowed` | 不换色，保持形状 |

**插图三色体系**（实现 B）：`illustration-background` / `illustration-surface` / `illustration-detail`，深浅主题各有映射。插图只允许用这三色 + 状态色，不引入新色。

**空状态文案规则**：标题说"这里是什么"，副文说"怎么让它有东西"，按钮说"现在做什么"。三段缺一不可。

## 5. 长列表

| 问题 | 解法 |
|---|---|
| 万级会话列表卡顿 | 虚拟滚动（固定行高最省事，实现 B栏行 32–36） |
| 滚动条跳动 | `scrollbar-gutter: stable` |
| 悬停时列表抖动 | hover 只改背景，不加 border/transform |
| 图片撑破布局 | `aspect-ratio` + `object-fit: cover` |
| 长标题溢出 | `min-width: 0` + `truncate`（缺前者 flex 不会收缩） |
| 滚动容器内 sticky 头 | 用 `position: sticky; top: 0` + 背景不透明 |

## 6. 快捷键与命令面板

| 项 | 规格 |
|---|---|
| 键帽 | 16×16（高），圆角 4，11px，`label-tertiary` 底 |
| 键帽间距 | 2px |
| 菜单右侧提示 | 与文字 `gap: 8px`，右对齐 |
| 命令面板宽 | `min(640px, 100vw - 48px)` |
| 面板最多可见项 | 8–10 行（超出的滚动） |

**注意**：平台差异必须处理（⌘ vs Ctrl）。实现 B 用 `html[data-platform='darwin']` 区分，而不是运行时字符串拼接——避免首屏渲染错键位。

## 7. 跨模式的通用规则

1. **任何点击目标 ≥ 24×24**，图标视觉 16px 时用 padding 补足热区。
2. 图标按钮必须有 `aria-label` 或可见文字，二者取其一。
3. 破坏性操作的颜色只出现在按钮/图标上，不染整块区域。
4. 所有浮层都能 `Esc` 关闭，且关闭后焦点回到触发元素。
5. 模态打开时锁定背景滚动，并给 `<body>` 加 `padding-right` 补偿滚动条宽度。
6. 加载态不改变容器尺寸（用占位而非替换）。
