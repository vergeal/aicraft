# IT 工单

用 `itsm.*` 工具把一次长虹 ITSM 工单填报**准备好**，交给应用里的「IT 工单」页面去浏览器里执行。工具本身不驱动
浏览器，也不会提交任何工单。

## 什么时候用

- 用户说「帮我提个堡垒机权限」「申请测试环境堡垒机」「准备一下发版工单」时，先用 `itsm.services` 看有哪些可填的
  工单类型。
- 从用户话里提取答案（系统名、原因、资源关键词、账号、发布窗口等）后，用 `itsm.prepare` 排入待办，把缺失的必填项
  一次问清。
- 用户问「好了吗 / 提交了吗 / 工单号多少」时，用 `itsm.status`；要看最近做过什么，用 `itsm.history`。

## 必须遵守

1. **绝不代用户提交。** 你的职责到「准备好答案」为止。工作台会把页面填到提交前；堡垒机第一页提交需要用户在界面上
   二次确认，且只能由用户点击。
2. **缺失的必填项要先补齐。** `itsm.prepare` 会返回 `missing`，把每一项的名称转述给用户并等待回答，不要编造。
3. **不猜页面选项。** 业务系统、项目类型、原因分类这些下拉以页面为准；`itsm.services` 返回的 `defaults` 只是页面
   常见默认值，用户没确认就当作待确认。
4. **不保存任何口令。** 只记录账号标签与内嵌浏览器的登录态分区；OA 密码不经过工具。
5. 发版工单的标题、发布方案、回退方案可以让插件内的临时会话生成，但生成结果必须经用户在向导里确认。

## 工具速查

| 工具 | 作用 |
|---|---|
| `itsm.services` | 列出可填的工单类型（内置模板 + 已同步目录里的服务项）与每个模板的必填字段 |
| `itsm.prepare` | 按模板合并答案（含上次保存的值），写入待办队列，返回 `requestId` 与 `missing` |
| `itsm.status` | 查一次待办/执行的进度、当前步骤、结果与工单号 |
| `itsm.history` | 最近记录：时间、类型、标题、工单号、状态 |

## 示例

```
itsm.services {}
→ 返回 { templates: [{ id: "fortress-prod", name: "生产堡垒机申请", required: ["title", "reason", ...] }] }

itsm.prepare { templateId: "fortress-prod", values: { title: "XX 系统投产权限申请", keywords: "xx-app,xx-db" } }
→ { requestId: "req_…", missing: ["projectType", "approver", "reason"] }
```

把 `missing` 转成具体问题问用户，补齐后再调用一次 `itsm.prepare`，然后告诉用户「已准备好，请到左侧「IT 工单」页面
确认并开始填写」。
