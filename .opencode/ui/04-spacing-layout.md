# 04 · 间距、尺寸与布局

## 1. 间距基准

**两侧都用 4px 基准，但没有一侧把它做成了完整的全局阶梯。**

| | 实现 A | 实现 B |
|---|---|---|
| 基准 | `--spacing: 4px` | 无基准变量，直接写 px |
| 表达 | `calc(var(--spacing) * N)`，N 可为小数（1.5、6.5） | 组件内局部变量或字面量 |
| 最高频 | `gap-2`（8px，1315 次）、`gap-3`（12px，735）、`gap-4`（16px，512）、`gap-1`（4px，580）、`gap-0.5`（2px，192）、`gap-1.5`（6px，255） | `4 / 6 / 8 / 12 / 16 / 20 / 24` |

### 实际节奏（可直接采用）

| 关系 | 值 | 场景 |
|---|---|---|
| 图标与文字 | 4–6px | Button `gap: 4px`、Pill `gap: 4px`、实现 B Sidebar label `6px` |
| 同组控件 | 8px | 输入框内图标与文本、Tooltip `gap: 8px` |
| 相邻控件 | 12px | 工具栏按钮组 |
| 不同组 | 16px | 卡片内区块、会话列表项 `--conversation-item-gap: 16px` |
| 区块之间 | 20–24px | Modal `gap: 20px`、页面边距 |

> 规则：**间距只用 2 的倍数，优先 4/8/12/16/20/24**。`2px` 只允许出现在图标与文字的微调、以及 1px 边框的补偿里。

## 2. 控件尺寸阶梯

实现 A 有完整的 10 档（`--control-size-*`，rem 换算 @16px）：

| 档 | 值 | px | 典型用途 |
|---|---|---|---|
| `4xs` | 1.25rem | 20 | 极小图标按钮 |
| `3xs` | 1.375rem | 22 | 标签内控件 |
| `2xs` | 1.5rem | 24 | Pill、小图标按钮 |
| `xs` | 1.625rem | 26 | 紧凑行操作 |
| `sm` | 1.75rem | 28 | 小按钮、菜单项 |
| `md` | 2rem | 32 | **默认输入框/按钮** |
| `lg` | 2.25rem | 36 | 主按钮、对话框操作 |
| `xl` | 2.5rem | 40 | 大按钮、登录页输入 |
| `2xl` | 2.75rem | 44 | 落地页 |
| `3xl` | 3rem | 48 | 落地页大按钮 |

实现 B 只显式做了两档，但其余组件都落在同一数轴上：

| 组件 | 高度 | 水平内距 | 字号 |
|---|---|---|---|
| Button `md` | 36 | 14 | 14/22 |
| Button `sm` | 28 | 10 | 12/18 |
| Input | 32 | 8 | 14/22 |
| Pill | 24 | 8 | 12/18 |
| Tag | 17（行高） | 8 | 11/17 |
| Switch | 20 | — | — |
| SegmentedControl tab | 28 | 16 | 13/20 |
| Tooltip | 内容撑开 | 3 竖 / 7 横 | 13/20 |

**对齐关系**：实现 B 的 28 / 32 / 36 正好是 实现 A 阶梯里的 `sm / md / lg`。说明这套数轴是跨产品共识。

## 3. 内边距模式

| 模式 | 值 | 出处 |
|---|---|---|
| 胶囊/标签 | `padding: 1px 8px` | 实现 B Tag |
| 小控件 | `0 8px` / `0 10px` | 实现 B Input / Button sm |
| 默认按钮 | `0 14px` | 实现 B Button md |
| 分段控件容器 | `4px`（四周） | 实现 B SegmentedControl |
| 浮层内容 | `24px` | 实现 B Modal |
| 浮层标题区 | `22px 14px 12px 24px`（非对称，右侧留给关闭按钮） | 实现 B Modal |
| 卡片 | `p-4`（16px） | 实现 A 高频 |

**非对称内边距是刻意设计**：Modal 头部右侧 14px 是为了让 28px 的关闭按钮与内容边缘视觉对齐；不是笔误。

## 4. 圆角与尺寸的配比

| 控件高度 | 推荐圆角 | 证据 |
|---|---|---|
| 17–24（Tag/Pill） | 999px（胶囊） | 两侧一致 |
| 28–32 | 8px | 实现 B `radius-sm`、实现 A `control-radius-sm` |
| 36 | 12px | 实现 B Button md、实现 A `--control-radius-lg: 10px` |
| 浮层/对话框 | 20–28px | 实现 A `radius-xl 20`；实现 B `radius-panel 28` |

即：**小控件用 8，中控件 10–12，浮层 20–28**。控件圆角与高度之比保持在 0.3 左右最协调。

## 5. 布局骨架

### 三栏结构（实现 B）

```
┌────────────┬──────────────────────────────┬──────────────┐
│ 侧栏        │ 会话区                        │ 右栏          │
│ 280 / 56    │ 内容宽 clamp(680, col*0.64, 920) │ 默认 45% 宽   │
└────────────┴──────────────────────────────┴──────────────┘
```

关键常量（`ui-layout/src/client/columns.ts`）：

| 常量 | 值 | 含义 |
|---|---|---|
| `SIDEBAR_DEFAULT` | 280px | 侧栏展开 |
| `SIDEBAR_COLLAPSED` | 56px | 图标栏 |
| `SIDEBAR_AUTO_COLLAPSE` | 1024px | 低于此宽度自动折叠 |
| `SIDEBAR_DRAWER_BREAKPOINT` | 768px | 低于此宽度转抽屉 |
| `RIGHTBAR_DEFAULT_RATIO` | 0.45 | 右栏占视口比例 |

会话区：

| 变量 | 值 |
|---|---|
| `--chat-content-width` | `clamp(680px, 列宽 × 0.64, 920px)` |
| `--composer-card-max-width` | 内容宽 + 32px |
| `--composer-stack-gap` | 6px |
| `--composer-text-max-height` | 336px |
| `--chat-flow-gap` | 4px |
| `--assistant-block-gap` | 16px |

### 阅读宽度（实现 A）

| 变量 | 值 |
|---|---|
| `--page-default-reading-width` | 730px |
| `--page-content-max-width` | 1440px |
| `--dashboard-content-inline-inset` | 44px |
| `--conversation-item-gap` | 16px |
| `--conversation-grouped-item-gap` | 4px |

> **共同点**：对话正文宽度 680–920px，长文阅读 730px。**超过约 900px 后，行宽会让视线回扫变累**——两侧都主动限制了正文宽度，而不是随窗口拉伸。

### 断点策略

| 来源 | 断点 |
|---|---|
| 实现 B JS（容器宽度，`ResizeObserver`） | 768 / 1024 |
| 实现 B CSS | 400 / 480 / 560 / 720 / 760 / 767 / 1100 / 1200（767 出现 13 次 = 移动端主断点） |
| 实现 A | 以 工具类框架 默认 + 容器查询为主 |

真正的重点不是断点值，而是：**实现 B 用交互能力查询远多于尺寸断点**——304 处 `@media (hover: hover)`、12 处 `pointer: coarse`、11 处 `hover: none`。

## 6. 布局落地规则

1. 侧栏宽度不要出现非 8 倍数；280/56 是验证过的组合。
2. 正文列宽设上限（700–900px），宁可留白不要拉满。
3. 输入区与内容区同宽，输入框外扩 16px（`+32px` 总宽）让焦点环不贴边。
4. 折叠状态必须有独立宽度常量（56px），不要靠 `display:none`。
5. 用容器查询（`cqi`/`cqw`）而非视口查询判断"这一栏够不够宽"，因为同一断点下三栏和单栏的可用宽度完全不同。
