# 用户说话风格标准

风格档案用来让 AI 代写消息时「像本人写的」，而不是通用客服腔。学的是**本账号自己发出的文本消息**，存储在插件数据目录，从不外发。

## 存储

```text
<plugin data>/hyt/style/<account>.json   每个账号一份档案
<plugin data>/hyt/ai-sent.json           AI 自己发出的消息 id（最多 2000 条）
```

`<account>` 是本地账号目录名，例如 `csT1002173`。档案读写都在 `profile.ts`，写入用「临时文件 + rename」替换。

## 档案结构

```jsonc
{
  "tone": "简洁",                  // 未知 | 简洁 | 平和 | 详细 | 热情
  "avgLength": 14.2,               // 平均字数，平滑后
  "emojiRate": 0.03,               // 含表情的消息占比
  "punctuation": { "comma": 0, "period": 0, "exclamation": 0, "question": 0, "ellipsis": 0 },
  "greetings": ["好的", "收到"],     // 常用开场，最多 6 个
  "closings": ["谢谢", "辛苦了"],    // 常用收尾，最多 6 个
  "favoritePhrases": ["稍等", "我看下"], // 口头习惯，最多 10 个
  "examples": [{ "text": "我看下，十分钟回你", "at": "2026-11-22T08:00:00.000Z" }],
  "antiPatterns": ["不要用表情符号", "不要写长段落"],
  "updatedAt": "2026-11-22T08:00:00.000Z"
}
```

- `tone` 由平均长度、表情率和感叹号数量推出，不是模型判断。
- `antiPatterns` 同样是统计结论：本人几乎不用表情、不写长段、不用感叹号或省略号时，明确写成「不要模仿」。
- `examples` 最多保留最近 30 条，按归一化文本去重。

## 样本来源与预过滤

只学习**本账号发出、`MsgType = 1` 的文本**。进入统计前必须通过 `filterSamples` / `isLearnable`：

1. 文本去首尾空白后少于 4 个字：丢弃。
2. 纯链接：丢弃。
3. 纯表情或纯标点：丢弃。
4. 批内重复，或归一化后已经学过的文本：丢弃（保留第一次出现）。
5. 消息 id 在 `ai-sent.json` 里（AI 自己发的）：丢弃。否则档案会把 AI 的措辞当成用户本人的措辞，越学越偏。

发送成功后 `markSent` 记录消息 id，这是第 5 条的唯一数据来源。

## 增量合并

`mergeSamples(profile, samples, now)` 是纯函数，不调用模型：

- 平均长度、表情率用 `0.3` 的平滑权重向新批次靠拢，避免一批异常样本把档案带偏；
- 标点计数累加，不做平滑；
- 开场 / 收尾 / 口头习惯按出现顺序去重后截断；
- 语气与「不建议模仿」每次重算；
- 空批次直接返回原档案，不刷新 `updatedAt`。

## 使用

- `hyt.style.get` 返回档案与一段摘要（`describeProfile`）。
- 代写消息时应先读风格档案，遵守 `antiPatterns`，开场与收尾优先从 `greetings` / `closings` 里选，示例只用来对齐语气，不要整句照抄。
- 自动回复默认只出草稿；是否真正发送由白名单与托管的开关决定。

## 维护

- 样本量不足时档案会停留在「未知」，这是预期行为，不要用少量样本硬凑语气。
- 需要重置时删除对应 `<account>.json` 即可；`ai-sent.json` 与档案相互独立，删档案不必删它。
- 换账号时按账号目录分别保存，不共享档案。
