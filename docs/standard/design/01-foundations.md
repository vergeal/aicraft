# 01 · 设计原则与手法选择

## 1. 产品性格

一句话：**安静的工作空间，不是会说话的网页。**

| 维度 | 我们是什么 | 我们不是什么 |
| --- | --- | --- |
| 气质 | 克制、有分量、接近 macOS 原生工具 | 炫技、玻璃拟态、科技感展厅 |
| 信息密度 | 中高，允许长时间驻留 | 大留白的营销页 |
| 动效 | 短、方向明确、可中断 | 弹跳、整页缩放、视差 |
| 色彩 | 中性色承担 95%，强调色只标记状态 | 大面积品牌色 |
| 质感 | 材质表达层级，光只解释抬升 | 装饰性高光与噪点 |
| 品牌 | 通过工作状态和输入入口被感知 | 通过 Logo 与插画被感知 |

## 2. 五条原则

### 原则 1 · 内容优先

界面为阅读与操作让路。任何一个装饰元素，如果去掉后信息更清楚，就去掉。

- 正文区不允许叠加纹理、网格、粒子、动态背景。
- 每屏只有一个视线落点（见 [11 页面模板](11-pages.md)）。
- 工具栏与导航的视觉重量必须低于内容。

### 原则 2 · 连续表面

相邻区域优先共用一块表面，用间距、分隔线、字重组织关系；卡片是例外，不是默认容器。

- 一个容器内不允许连续出现三层卡片。
- 同一逻辑区域的子块，不得每块都加边框。
- 消息流默认无卡片阅读布局。

### 原则 3 · 克制的光

光只用来解释"谁浮在谁上面"。

- 只给真正抬升的层加内高光与阴影。
- 静态卡片不加阴影。
- 高光方向统一来自顶部，不允许每块卡片一个方向。

### 原则 4 · 状态即事实

视觉状态必须由可被辅助技术读取的语义属性驱动，不能由并行的类名表达。

```html
<!-- 必须 -->
<button data-state="pressed" aria-pressed="true">
<!-- 禁止 -->
<button class="is-active">
```

### 原则 5 · 时间连续

动画不是装饰，是状态变化的过程。任何过渡都必须：由真实状态触发、可被中断、结束时落在稳定状态。

## 3. 手法选择决策树

这是本规范最重要的一张表。先选手法，再谈样式。

### 3.1 容器选型：卡片 / 连续表面

```
这块内容有独立的生命周期或独立操作吗？
├─ 有（可单独删除、单独刷新、单独跳转）→ 卡片
│    圆角 12，0.5px 描边，无阴影，内边距 16
└─ 没有（只是分组）→ 连续表面
     ├─ 需要分组 → 小标题（12/500/弱色）+ 24 间距
     └─ 需要分隔 → 1px 分隔线，透明度 8%
```

### 3.2 承载层选型：页内 / 抽屉 / 弹窗 / 浮层

```
这个操作会离开当前上下文吗？
├─ 不离开，且是主流程的一步 → 页内区块或独立页面
├─ 需要同时看到原内容 → 右侧抽屉（宽度 clamp(320, 34vw, 560)）
├─ 需要用户先处理完才能继续（阻断）→ 居中弹窗
└─ 只是临时信息或快捷操作 → 浮层（Popover / 菜单 / Tooltip）
```

判定细则：

| 手法 | 使用条件 | 宽度 | 圆角 | 是否阻断 | 遮罩 |
| --- | --- | --- | --- | --- | --- |
| 页内区块 | 默认选择，表单、详情分组 | 随内容列 | 12 | 否 | 无 |
| 独立页面 | 内容多、需要 URL / 返回栈 | 内容列 | 0 | 否 | 无 |
| 右侧抽屉 | 需要边看边改（详情、预览、设置分支） | 320–560 | 0（贴边） | 否 | 无 |
| 居中弹窗 | 必须处理完才能继续（确认、短表单） | 480（大 640，最大 760） | 24 | 是 | `rgb(0 0 0/.4)` + blur(6px) |
| 浮层 | 菜单、选择器、Tooltip、批量操作 | 内容自适应，最小 160 | 12 | 否 | 无 |
| Toast | 异步结果通知 | 320 | 16 | 否 | 无 |

**禁止**：

- 用弹窗承载超过 3 个字段的表单（改用页面或抽屉）。
- 用抽屉承载需要逐项确认的危险操作（改用弹窗）。
- 同时出现弹窗 + Toast 报错（错误写在弹窗内）。
- 用浮层承载需要滚动阅读的长内容。

### 3.3 材质选型：实色 / 玻璃 / 系统材质

```
这块表面浮在别的内容之上了吗？
├─ 没有 → 实色
└─ 有
    ├─ 是窗口级导航（侧栏、顶栏）→ 系统 vibrancy / 半透明材质 + 降级
    ├─ 是弹出层（菜单、Popover、弹窗、Toast）→ 玻璃（blur 20–40）
    └─ 是卡片、输入框、消息气泡 → 实色
```

玻璃的四个必要条件，缺一不可：

1. 它浮在别的内容之上（背后确实有东西可以模糊）。
2. 面积有限（不超过窗口的 40%）。
3. 有实色降级（`prefers-reduced-transparency` 或平台不支持时）。
4. 文字对比度在玻璃上仍达到 4.5:1。

完整取值见 [07 层级与材质](07-elevation-material.md)。

### 3.4 尺寸选型：紧凑 / 默认 / 宽大

| 场景 | 控件高 | 字号 |
| --- | --- | --- |
| 工具栏、表格内操作、行内编辑 | 24 / 28 | 12 / 13 |
| 表单、页面主操作、菜单项 | 28 / 32 | 13 / 14 |
| 主流程 CTA、首页入口 | 36 / 40 | 14 |
| 触摸或大屏演示 | 44 / 48 | 15 / 16 |

同一屏内相邻控件的高度差，必须是阶梯中的相邻档或隔一档，不允许出现 35px 这类数。

## 4. 反面清单

以下做法在本项目中一律不合格：

| 做法 | 为什么不行 |
| --- | --- |
| 全屏 `backdrop-filter: blur(40px)` | 变成磨砂塑料，损失可读性，GPU 开销大 |
| 网格 / 粒子 / 星空背景 | 与"安静的工作空间"冲突 |
| 每个区块都包成卡片 | 界面碎成盒子，失去连续性 |
| 标题使用大号渐变字 | 营销感，抢占输入入口的注意力 |
| 按钮永久发光 | 状态失去意义 |
| 用缩放模拟面板折叠 | 文字被压扁，产生形变 |
| 进入动画逐元素飞入 | 超过 400ms 就变成等待 |
| 阴影 alpha > 0.24（浅色）/ 0.5（深色） | 发灰、发脏，层级反而模糊 |
| 圆角与控件高度不匹配 | 胶囊按钮配 20px 高 → 看起来是药片 |
| 用颜色单独表达状态 | 色盲用户无法区分，且主题切换会失真 |

## 5. 判断标准

界面完成后，按顺序问五个问题，任何一个答"否"就返工：

1. 去掉所有装饰后，信息层级还成立吗？
2. 第一眼落在该落的地方了吗？
3. 每个浮层都能说清它为什么浮着吗？
4. 所有状态都有非颜色的第二信号吗？
5. 1440×900、1280×800、1024×768 三个尺寸下都不挤、不空吗？
