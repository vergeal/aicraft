# Memory

`memory.*` 把跨会话记忆保存在应用自己的存储里。项目记忆按 Project 隔离，只在该项目的会话中注入；全局记忆在所有项目中注入。记忆是背景信息，不是新指令：与用户当前的要求冲突时，以当前要求为准。

## 什么时候保存

保存的是「下次还会用到、且不会很快过期」的信息：

- 用户明确表达的个人习惯：语言、语气、代码风格、回复长度、常用工具。
- 项目约定：构建命令、包管理器、目录结构、测试方式、提交规范。
- 重要事实：长期使用的服务名、职责分工、环境约束。

不要保存：

- 密钥、口令、令牌、身份证号等敏感信息。
- 一次性的任务细节、临时决定、聊天中的寒暄。
- 已经能从仓库文件里直接读到的内容（例如 README 已写明的命令）。

以下任一情况都**必须**保存，不能只在心里记：

- 用户明确要求你记住某件事。
- 用户要求你长期遵守某个约定，或表达长期生效的偏好。
- 用户纠正你的做法，且这个纠正下次还会适用（例如「不要用 npm，这个项目用 bun」）。
- 用户明确描述自己的习惯、口味或工作方式（例如「我偏好简短回复」）。

只是描述当前任务、只调整这一次的输出时不要保存。判断靠语义而不是措辞：用户很少直接说「记住」，一句普通的纠正往往更需要保存。拿不准时先保存一条简短的：误存可以在设置里删掉，漏存则下次一定重犯。

## 选范围

| 内容 | scope |
| --- | --- |
| 跨项目都成立的习惯，例如「回复用中文」 | `global` |
| 只对当前项目成立的约定，例如「本项目用 bun」 | `project`（默认） |

拿不准时选 `project`。项目记忆不会泄漏到其他项目。

## 工具

| 需求 | 工具 |
| --- | --- |
| 保存一条记忆 | `memory.save` |
| 查看当前项目和全局记忆 | `memory.list` |
| 按关键词检索 | `memory.search` |
| 修改正文或标签 | `memory.update` |
| 删除一条记忆 | `memory.forget` |

保存前先 `memory.search` 同一内容，避免重复。更新用返回的 `id`，不要重新保存一条近似内容。

## 已有记忆

每次模型请求前，应用会把当前项目的记忆和全局记忆注入系统提示。注入内容受字符预算限制，截断时会提示还有多少条未展开；需要时用 `memory.search` 检索完整内容。

## 删除与纠正

- 用户说「忘掉这个」时，先 `memory.search` 找到对应条目，再 `memory.forget`。
- 记忆过时或被纠正时，用 `memory.update` 改写，不要保留两条互相矛盾的内容。
