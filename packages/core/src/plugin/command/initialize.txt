Create or update `AGENTS.md` for this repository.

The goal is a compact instruction file that helps future AI Craft sessions avoid mistakes and get productive quickly. Every line should answer: "would an agent very likely miss this without help?" If the answer is no, do not write it.

Concerns or constraints the user provided (always honour them):
$ARGUMENTS

## How to investigate

Read the highest-value sources first:
- `README*`, root manifests, workspace configuration, lockfiles
- build, test, lint, format, typecheck, and code-generation configuration
- CI workflows and pre-commit / task runner configuration
- existing instruction files (`AGENTS.md`, `CLAUDE.md`, `.cursor/rules/`, `.cursorrules`, `.github/copilot-instructions.md`)
- repository-local AI Craft configuration such as `aicraft.json`

If the architecture is still unclear after reading configuration and docs, inspect a few representative code files to find the real entry points, package boundaries, and execution flows. Prefer files that show how the system connects over random leaf files.

Trust executable sources of truth over prose. Where documentation conflicts with configuration or scripts, believe the executable source and keep only what you can verify.

## What to extract

Look for the facts most valuable to an agent working in this repository:
- exact developer commands, especially the non-obvious ones
- how to run a single test, a single package, or a focused verification step
- command ordering when it matters, for example `lint -> typecheck -> test`
- monorepo or multi-package boundaries, ownership of the main directories, and the real app/library entry points
- framework or toolchain quirks: generated code, migrations, codegen, build artifacts, special environment loading, dev servers, infrastructure deployment flows
- testing quirks: fixtures, integration test prerequisites, snapshot workflows, required services, flaky or expensive suites
- important constraints worth keeping from existing instruction files

Good `AGENTS.md` content is hard-won context that would take reading several files to infer.

## Asking questions

Ask the user only when the repository cannot answer an important question. Ask at most a small batch of questions with the `question` tool.

Good questions:
- undocumented team conventions
- expectations around branches / PRs / releases
- known but unwritten missing setup or test prerequisites

Do not ask anything the repository already states.

## Writing rules

Include only high-value, repository-specific guidance, such as:
- exact commands and shortcuts an agent would otherwise guess wrong
- architecture notes that cannot be inferred from file names
- conventions that differ from language or framework defaults
- setup requirements, environment quirks, and operational gotchas
- references to important existing instruction sources

Exclude:
- generic software advice
- long tutorials or exhaustive file trees
- obvious language conventions
- speculative claims or anything you cannot verify
- content better kept in another file and referenced through `instructions` in `aicraft.json`

When in doubt, leave it out.

Prefer short sections and bullets. Keep the file simple if the repository is simple. If the repository is large, summarise the few structural facts that genuinely change how an agent works.

If an `AGENTS.md` already exists at `${path}`, improve it in place rather than rewriting blindly. Keep verified, useful guidance; delete filler and stale claims; and reconcile it with the current codebase.
