# 13 · 国际化与 CJK 排版

## 1. 字体栈顺序（最容易出错的一步）

```
拉丁/系统优先，CJK 兜底：
-apple-system, BlinkMacSystemFont, "Segoe UI",
"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei",
"Helvetica Neue", Helvetica, Arial, sans-serif
```

三条规则：

1. **拉丁字体必须排在 CJK 字体之前**。反过来的话，中文界面里的英文和数字会被 CJK 字体的西文部分接管，字宽、字形都会偏离产品风格。
2. **CJK 字体按平台给全**：macOS `PingFang SC`、旧版 macOS `Hiragino Sans GB`、Windows `Microsoft YaHei`。缺一个就会在该平台回退到衬线字体。
3. **代码字体栈结尾不要裸 `monospace`**。Windows 下 `monospace` 常解析为宋体/SimSun，中英混排立刻断裂。正确做法是显式列出 `Consolas, "Liberation Mono", Menlo, Courier` 后再补 CJK 字体。

## 2. 行高：CJK 需要更松

| 场景 | 西文 | 中文 |
|---|---|---|
| 正文 | 1.45–1.5 | **1.55–1.65** |
| 小字标注 | 1.4 | 1.5 |
| 标题 | 1.25–1.33 | 1.35–1.4 |

素材实测的 `14px / 22px`（1.57）正好落在中文舒适区间；英文界面用同样值会略松，但不影响可读性。**统一按中文取值，英文侧只赚不亏**；反之（按英文 1.45 排中文）会显得拥挤。

若产品同时支持两种语言，用 `:lang()` 微调而不是换整套字号：

```css
:lang(zh), :lang(ja), :lang(ko) { line-height: 1.65; }
```

## 3. 字号下限

| 内容 | 最小 |
|---|---|
| 中文正文 | 12px |
| 中文标注 | 11px（仅在短标签、数字密集场景） |
| 中文按钮 | 12px |
| 纯英文/数字标注 | 10px 可接受 |

中文在 11px 以下笔画开始粘连，尤其「量、墨、赢」这类多笔画字。**11px 只给英文或纯数字**，中文密集处宁可用 12px。

## 4. 中英混排

三条微排版规则，优先级从高到低：

1. **中文与英文/数字之间留半角空隙**。文字稿阶段用空格，或使用引擎能力：
   ```css
   :lang(zh) { text-autospace: normal; }   /* Chromium 122+，不支持时不影响 */
   ```
2. **中文内用全角标点，句子结尾用中文句号**；引号用「」或 ""，全产品统一。
3. **括号内外语言一致**：中文语境用全角（），包裹英文时可用半角 () 但前后不加空格。

## 5. 断行与溢出

```css
/* 中文：按字断行，但遵守避头尾 */
:lang(zh) {
  line-break: strict;        /* 不允许标点出现在行首 */
  word-break: normal;        /* 关键：不要用 break-all，会切断英文单词 */
  overflow-wrap: break-word;
}

/* URL / 路径 / 哈希：允许任意位置断 */
.wrap-anywhere { overflow-wrap: anywhere; }

/* 西文长词 */
:lang(de) { hyphens: auto; }
```

**禁止**：全局 `word-break: break-all`。它会把英文单词从中间切开，且对中文没有额外收益。

**行首禁则**：`，。、；：？！）》」』` 不能出现在行首；`（《「『` 不能出现在行尾。`line-break: strict` 覆盖大部分，剩余靠 `text-spacing-trim`（Chromium 支持）或手动不换行。

## 6. 宽度自适应

中文比英文短 30–40%，这带来两个相反的问题：

| 问题 | 解法 |
|---|---|
| 按钮固定宽 → 英文溢出 | 按钮 `min-width` + `padding: 0 14px`，不设固定宽 |
| 翻译成德文后同位置放不下 | 容器用 `flex` + `min-width: 0`，允许换行或收缩 |

**导航项、Tab、按钮一律按内容撑开**；需要等宽时（如分段控件）用 `flex: 1` 而不是写死 px。

## 7. 截断

| 场景 | 做法 |
|---|---|
| 单行（文件名、会话标题） | `overflow: hidden; text-overflow: ellipsis; white-space: nowrap` + 父级 `min-width: 0` |
| 多行（卡片摘要） | `-webkit-line-clamp: 2`，最多 3 行 |
| 中文多行截断 | 同上；中文按字计，2 行约 40–50 字为上限 |
| 不要 | 用 `…` 手工拼接字符串（会把代理对/emoji 切断） |

## 8. 数字、日期与货币

| 项 | 规则 |
|---|---|
| 数字对齐 | `font-variant-numeric: tabular-nums`（表格、计数器、终端） |
| 千分位 | 按 locale 格式化，不手写 |
| 日期 | 用相对时间（"3 分钟前"）优先；绝对时间用 ISO 或 locale 格式，**不要 06/07/2026 这种歧义格式** |
| 货币 | 符号 + 代码（`¥ CNY`）避免歧义 |
| 单位 | 数字与单位之间留半角空格（`32 px` / `32 ms`） |

## 9. RTL（若支持阿拉伯语/希伯来语）

- 布局一律用**逻辑属性**：`margin-inline-start`、`padding-inline-end`、`inset-inline-start`。
- 图标方向的镜像：箭头、撤销、缩进类需镜像；播放、时钟、品牌 logo 不镜像。
- 滚动条位置、阴影方向随 `dir` 翻转。
- 数字与代码块保持 LTR（`dir="ltr"` 包裹）。

## 10. 测试矩阵

发布前至少回归这四项：

| 用例 | 检查点 |
|---|---|
| 中文 + 英文混排段落 | 行高、标点、混排空隙 |
| 德语/俄语长词 | 是否溢出、是否被切断 |
| 日文（假名 + 汉字） | 行首禁则、字体回退 |
| 中文界面 + 系统字号放大 | 表格/按钮是否挤压、是否换行 |

## 11. 落地规则

1. 字体栈拉丁在前、CJK 在后、代码字体不含裸 `monospace`。
2. 行高按中文取值（正文 1.55–1.65），用 `:lang()` 微调而非换档。
3. 中文最小 12px，11px 只给英文/数字。
4. 禁止全局 `break-all`；URL 类才用 `anywhere`。
5. 按钮/导航按内容撑开，等宽场景用 `flex: 1`。
6. 数字列开 `tabular-nums`，日期避免歧义格式。
7. 布局用逻辑属性，为 RTL 留出可能。
