# Tauri Icons

Here's the process I've been using to create icons:

- Save source image as `app-icon.png` in `packages/desktop`
- `cd` to `packages/desktop`
- Run `bun tauri icon -o src-tauri/icons/{environment}`
- Use [Image2Icon](https://img2icnsapp.com/)'s 'Big Sur Icon' preset to generate an `icon.icns` file and place it in the appropriate icons folder

The Image2Icon step is necessary as the `icon.icns` generated by `app-icon.png` does not apply the shadow/padding expected by macOS,
so app icons appear larger than expected.

Every smaller size in `icon.icns` must be a premultiplied-alpha downsample of its 1024px (`icon_512x512@2x`) image. Image2Icon's
smaller sizes had light, unpremultiplied anti-aliased edges that render as a halo on dark backgrounds, most visibly at the 64px size
macOS uses in System Settings lists. Regenerate them from the 1024px image and resync `dock.png` before committing a new `icon.icns`.

For unpackaged Electron on macOS, `app.dock.setIcon()` should use a PNG. Keep `dock.png` in each channel folder synced with the
extracted `icon_128x128@2x.png` from that channel's `icon.icns` so the dev Dock icon matches the packaged app inset.

## Current artwork (2026-11)

The mark now comes from `packages/ui/src/assets/brand/favicon-logo.svg`: a 24-unit grid with a 2-unit ring, scaled so the mark
fills 62% of the icon body. The three channels share that geometry and differ only in surface colour:

| Channel | Surface | Ring / core |
| --- | --- | --- |
| `prod` | `#171B22` edge → `#262F3C` centre lift | `#00E08A → #00D4A0 → #00B4FF` gradient, core `#99F6E4` |
| `beta` | `#3A3A3E` | same gradient, core `#99F6E4` |
| `dev` | `#00C79B` | inverted: ring and core `#0B1714` |

`prod`'s surface is a radial lift (centre at 50%/46%, reaching the edge colour at 66% radius) instead of a flat fill, so the
icon reads as a deep blue-grey with a slight lift rather than near-black on a dark desktop. To retune it, retint the surface
pixels of the existing artwork in place; the ring, keyline, shadow and anti-aliased edges must not be redrawn.

`dev` currently ships the `beta` artwork (same surface and mark) as a temporary state; the inverted dev palette above is the
design to restore when the channels need to be told apart again.

Geometry per asset:

- `icon.png`, small PNGs, `Square*Logo.png`, `StoreLogo.png`, `icon.ico`: rounded square at 94% of the canvas, corner radius
  22.37% of its side, transparent around it. A white keyline (0.45% of the canvas, 50% opacity, minimum 0.9px) and a soft
  drop shadow (`dy` 0.8%, blur 2%, 30%) keep the edge readable against the system selection background.
- `icon.icns`: 1024 canvas, 824 body centred at inset 100, corner radius 185, drop shadow `dy 12 / blur 22 / 30%`, plus a
  4px white keyline at 34% opacity. Every smaller layer is a premultiplied-alpha LANCZOS downsample of that 1024 master,
  and `dock.png` is its 256 render.
- `prod/icon.icon/Assets/icon.png`: 1024 square at 94%; Icon Composer applies the macOS mask.

Regenerating: render each master at 1024 with a transparent background, downsample with premultiplied alpha, then
`iconutil -c icns` from the 10-layer iconset. Do not use the old Tauri/Image2Icon flow for the current artwork.

Headless Chrome renders the viewport shorter than `--window-size` requests, so a square screenshot of a 1024 canvas crops the
bottom edge. Ask for extra height and crop the square back out before downsampling, or the icon loses its bottom corners.
